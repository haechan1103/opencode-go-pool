# 설정 따라 하기

**코드를 고치지 않아도 모델 목록과 조회·대기 시간을 바꿀 수 있습니다.** 설정 파일 한 개만 수정하세요.

## 1. 내 설정 파일 찾기

저장소 폴더의 터미널에서:

```sh
node bin/cli.js config
```

첫 줄에 `Config file: ...`로 표시된 경로가 수정할 파일입니다. 보통 macOS/Linux는 `~/.config/opencode/go-pool.json`, Windows는 `%APPDATA%\opencode\go-pool.json`입니다. XDG나 `OPENCODE_GO_POOL_CONFIG`를 쓰면 표시된 실제 경로를 따르세요.

아직 계정을 등록하지 않았다면 `node bin/cli.js add A`부터 실행하세요. 파일에 API 키를 적지 않습니다.

**JSON 파일 작성 규칙:** 항목 사이에는 쉼표를 넣고, 마지막 항목 뒤에는 쉼표를 넣지 않습니다. 모델 이름은 큰따옴표로 감쌉니다. 주석은 넣지 않습니다.

## 2. 사용할 모델 바꾸기

지원 모델의 정확한 이름:

```sh
node bin/cli.js models
```

### Kimi만 표시하기

기존 설정의 `accounts` 등은 유지하고 `models`를 다음처럼 바꿉니다.

```json
"models": ["kimi-k3"]
```

### 모델을 하나 더 표시하기

```json
"models": ["kimi-k3", "deepseek-v4.1-flash"]
```

### 포함된 모든 Go 모델 표시하기

설정에서 **`models` 항목 전체를 삭제**합니다. 앞뒤 쉼표도 맞춰주세요. `models: []`는 “모델 0개”라는 뜻이므로 전체 표시 용도로 사용하지 않습니다.

수정 후 OpenCode를 종료하고 다시 실행하면 모델 목록에 반영됩니다. 목록을 표시하는 설정이지, 지금 선택한 모델을 자동으로 교체하는 설정은 아닙니다. 실제로 사용할 모델은 OpenCode 안에서 직접 고릅니다.

### 이미지나 추론 강도는요?

- `models` 출력에 `image`가 포함된 모델은 카탈로그상 이미지 입력을 지원합니다.
- 추론 강도는 해당 모델이 지원하는 옵션을 OpenCode에서 선택합니다. DeepSeek V4.1 Flash의 경우 `low / high / max`입니다.
- 추론 강도 메뉴가 없는 모델도 있습니다. 없는 옵션을 임의로 설정하지 마세요.
- 모델별 기능은 `catalog/go-models.json`에서 가져옵니다. 새로운 공개 모델 정보를 반영하려면 `npm run catalog:update` 후 `npm run check`, 그리고 OpenCode 재시작을 합니다.
- 실제 모델 제공 여부와 권한은 Go 서버가 결정합니다.

## 3. 계정 순서 이해하기

```json
"accounts": ["A", "B", "C"]
```

A를 선택해서 사용하다 막히면 B, 그다음 C를 확인합니다. C를 선택했다면 다음은 A, 그다음 B입니다. **현재 계정이 사용 가능하면 그대로 유지**합니다.

같은 요청에서 이미 실패한 계정과 한도에 걸린 계정은 건너뜁니다. 순서를 바꾸거나 계정을 추가·삭제한 뒤에는 OpenCode를 재시작하세요. 키가 없는 계정 이름만 적어두면 그 계정은 사용할 수 없습니다.

## 4. 숫자 수정하기

모든 시간은 **분 단위**, 입력 범위는 **1~1440분**입니다. `0`은 지원하지 않습니다. 생략한 항목은 기본값을 사용합니다.

### 사용량 조회 간격 — `polling`

| 항목 | 기본값 | 뜻 |
| --- | ---: | --- |
| `idleMinutes` | 60 | 기본 사용량 조회 간격 |
| `activeMinutes` | 10 | 최근 사용한 계정의 조회 간격 |
| `activeWindowMinutes` | 20 | 마지막 사용 후 얼마 동안 “사용 중”으로 볼지 |

**자주 확인하고 싶다면:** 기본 1시간, 사용 중 5분, 마지막 사용 후 30분까지 자주 조회합니다.

```json
"polling": {
  "idleMinutes": 60,
  "activeMinutes": 5,
  "activeWindowMinutes": 30
}
```

**조회 요청을 줄이고 싶다면:** 기본 2시간, 사용 중 15분, 마지막 사용 후 30분까지 자주 조회합니다.

```json
"polling": {
  "idleMinutes": 120,
  "activeMinutes": 15,
  "activeWindowMinutes": 30
}
```

저장 후 다음 스케줄 확인부터 새 간격을 사용합니다. 스케줄러는 매분 확인하지만 매번 API를 호출하지 않습니다. 간격은 마지막 조회 시점부터 계산하므로 파일을 저장하자마자 바로 조회가 발생한다고 보장하지는 않습니다.

한도 리셋 시각이 지나면 다음 확인 때 더 일찍 재조회할 수 있습니다. 이 숫자들은 **조회 빈도**일 뿐 계정의 실제 한도를 늘리지는 않습니다.

### 오류 후 잠시 쉬는 시간 — `cooldowns`

어떤 계정에서 오류가 나면 다른 계정으로 전환하고, 실패한 계정을 잠시 제외합니다. 그 제외 시간을 정합니다.

| 항목 | 기본값 | 언제 사용하나요? |
| --- | ---: | --- |
| `quota` | 10 | 한도 오류가 났지만 실제 리셋 시각을 모를 때 |
| `auth` | 15 | 키 오류 등 인증 실패가 났을 때 |
| `rate` | 5 | 요청이 너무 많다는 오류 — 해당 계정·모델만 제외 |
| `service` | 2 | 서버·네트워크 오류 — 해당 계정·모델만 제외 |

예를 들어 인증 실패 후 임시 제외를 5분으로 줄이려면:

```json
"cooldowns": {
  "quota": 10,
  "auth": 5,
  "rate": 5,
  "service": 2
}
```

새 값은 **이후 발생하는 오류부터** 사용합니다. 이미 저장된 대기 시간을 바꾸려면 `go_pool_reset`을 사용하세요.

**중요:** Go 서버가 “내일 리셋”이라고 알려준 실제 한도는 `quota: 1`로 바꿔도 풀리지 않습니다. 알려진 리셋 시각이 우선합니다. 대기 시간을 줄인다고 잘못된 키가 유효해지는 것도 아닙니다.

## 5. 기본값 전체 예시

아래를 참고하되 `accounts`는 본인이 등록한 이름만 적으세요. `models`를 생략해서 전체 모델을 표시하는 예시입니다.

```json
{
  "enabled": true,
  "accounts": ["A", "B"],
  "polling": {
    "idleMinutes": 60,
    "activeMinutes": 10,
    "activeWindowMinutes": 20
  },
  "cooldowns": {
    "quota": 10,
    "auth": 15,
    "rate": 5,
    "service": 2
  }
}
```

저장 후 `node bin/cli.js config`로 문법과 현재 적용 설정을 확인합니다. `enabled: false`는 자동 조회·계정 전환을 중지합니다. 설치 때부터 false였다가 다시 켜는 경우 모델 등록을 위해 OpenCode를 재시작하세요.

## 6. 마지막 확인

1. `node bin/cli.js config` — 설정 파일을 읽을 수 있나요?
2. `node bin/cli.js status` — 등록한 계정의 키가 인식되나요?
3. `node bin/cli.js usage A` — A의 실제 조회가 성공하나요?
4. 모델·계정·키를 바꿨다면 **OpenCode를 재시작**했나요?
5. OpenCode에서 **Go Pool 계정의 모델**을 선택했나요?

macOS Keychain 방식은 터미널 창을 재시작할 필요가 없습니다. 환경변수 방식은 변경한 변수가 셸에 반영돼 있어야 합니다. 자세한 표는 [README의 재시작 안내](../README.md#무엇을-바꾸면-재시작해야-하나요)를 참고하세요.
